# AI 更晚阶段（Phase 3）方案 — 边界先于实现

**状态：方案定稿；默认不实现进 master 主链路。** 实现需单独里程碑与 Issue。

## 目标能力（候选）

1. **ES / 向量检索**：商品语义召回，供 `search-plan` / `recommend` 候选集，替代「仅 DB 列表抽样」。  
2. **行为推荐**：基于浏览/加购埋点的简单协同或重排（可先规则 + 向量混合）。  
3. **AI 写回运营动作**：例如「建议绑品/改文案」生成 **待审草稿**，人工确认后再写管理端 API。

## 硬边界（不变）

- **不** 进入支付、Lua 扣库存、MQ 落单主路径。  
- 写回必须 **人工确认** 或独立审批表；禁止模型直改 `flash_stock` / 订单状态。  
- 默认 `AI_ENABLED=false`；`platform.ai.features.*` 可按能力关断。

## 建议落地顺序

1. 检索：ES 商品索引 + mall 只读「候选供给」API → 再接 `recommend`。  
2. 埋点表 + 离线/近线特征 → 重排。  
3. 运营草稿表 + Admin 确认 API → 最后才谈自动写回。

## 与现有代码关系

- 现有：`platform-ai` 四类 API + 规则降级 + mall 只读组装快照。  
- Phase 3 只 **扩展候选来源与运营草稿**，不改 `GoodsStockCache` / `preCreateOrder`。
